# Argus

[English](../../README.md) · [繁體中文](README.zh-TW.md) · [简体中文](README.zh-CN.md) · [日本語](README.ja.md) · 한국어

**AI 에이전트에게**실행 중인**프로세스의 증거를 제공하는 MCP 서버.**

지금까지의 리버스 엔지니어링용 MCP 서버는 모두 *정적* 분석 도구 — Ghidra, IDA,
apktool — 로 이어지는 다리였습니다. 디스크 위의 파일을 에이전트에게 건네줄 수는 있지만,
프로그램이 지금 이 순간 실제로 무엇을 하고 있는지는 알려주지 못합니다.
저 버퍼에 무엇이 복호화되었는지, vtable 슬롯이 런타임에 어느 주소로 해석되었는지,
그 패킷을 보낸 것이 어느 호출 지점이었는지.

Argus는 그 나머지 절반입니다. 실행 중인 Windows 프로세스에 어태치하여 런타임 증거를
반환합니다. 실제 주소에 있는 실제 바이트, 실제로 실행된 코드의 디스어셈블,
해석된 IAT thunk, 살아 있는 메모리에서 따라간 호출 체인, 그리고 무엇이 입증되었고
무엇이 아직 추측인지를 구분하는 가설 원장입니다.

Argus는 모델을 대신해 결론을 내리지 않습니다. 주소, 모듈/RVA 컨텍스트, 명령어,
호출자, 피호출자, 국소적인 증거를 반환하고 그다음은 비켜섭니다.

## 이 프로젝트가 존재하는 이유

게임은 죽습니다. 운영사가 서버를 닫고, 스튜디오가 문을 닫고, 장르가 저물어 갑니다.
남는 것은 누군가의 하드디스크 위에서 더 이상 아무 곳에도 접속할 수 없게 된
클라이언트뿐입니다. 소스도 없고, 프로토콜 문서도 없고, 말을 걸 서버도 없습니다.
어떤 언어를 말하는 법은 여전히 기억하지만, 이제 아무도 듣지 않는 실행 파일만
남아 있습니다.

Argus는 그것들을 되살리기 위해 만들어졌습니다.

죽은 게임의 서버를 재구성한다는 것은 그 프로토콜을 복원한다는 뜻입니다.
패킷 구조, 암호화, 오피코드 디스패치, 회선 반대편의 상태 기계.
그리고 살아남은 유일한 명세서는 클라이언트 바이너리 그 자체입니다.
필요한 문서는 애초에 아무도 써 두지 않았고, 알고 있던 사람들은 이미 오래전에
흩어졌습니다.

정적 분석은 어느 지점까지는 데려다줍니다. 하지만 20년 된 클라이언트는 패킹되어
있고, 문자열은 암호화되어 있으며, 핸들러는 프로세스가 뜬 뒤에야 존재하는 테이블을
거쳐 디스패치됩니다. 그래서 실제로 실행시켜 놓고 그것이 동작하는 모습을 지켜봅니다
— 다음 절이 바로 그 이야기입니다.

이 도구의 목적은 거기에 있습니다. 살아 있는 것에 침입하기 위해서가 아니라,
죽어 버린 것이 다시 입을 열게 하기 위해서입니다.

## 왜 실행 중인 프로세스까지 들어가는가

**CPU는 암호문을 실행할 수 없습니다.**

프로그램이 디스크 위에서 스스로를 아무리 보호하더라도 — 패킹, 문자열 암호화,
명령어 가상화, 로드 시점에 해석되는 import — 프로세서가 그 코드를 실행하기 전에
그 모든 것을 되돌려 놓아야 합니다. 실행되는 그 순간, 진짜 명령어와 진짜 데이터는
평문 상태로 메모리에 놓여 있습니다. **그럴 수밖에 없습니다.**
이것은 특정 보호 도구가 잘못 만들어졌다는 이야기가 아니라 프로세서의 동작 방식에서
비롯되는 필연이며, 난독화를 아무리 겹쳐도 우회할 수 없습니다.

즉, 두 접근 방식은 애초에 서로 다른 것을 읽고 있습니다.

- **정적 분석이 읽는 것은 파일.** 제작자가 내놓은 그것.
- **런타임 분석이 읽는 것은 파일이 변한 결과.** 기계가 실제로 돌리고 있는 그것.

둘이 어긋날 때, 진실은 후자 쪽에 있습니다.

| 상황 | 정적 분석 도구 | Argus |
|---|---|---|
| 패킹 / 자가 복호화 코드 | 패커가 보임 | 메모리에서 풀린 바이트를 디스어셈블 |
| vtable을 통한 간접 호출 | `call [rax+0x18]`가 보임 | 슬롯을 구체적인 대상으로 해석 |
| 런타임에 해석되는 import | thunk 스텁이 보임 | thunk를 실제 API로 해석 |
| 복호화 이후의 버퍼 내용 | 알 수 없음 | 평문을 읽어냄 |
| 40개의 호출 지점 중 실제로 발생한 것 | 추측 | 실행된 것을 기록 |

### 정적 분석이 앞서는 지점

반대 방향의 트레이드오프도 분명히 적어 둡니다. 정적 분석 도구는 한 번도 실행되지
않는 것까지 포함해 **모든** 경로를 볼 수 있습니다. Argus가 볼 수 있는 것은 실제로
실행된 부분뿐입니다. 지나가지 않은 분기는 런타임 증거를 전혀 남기지 않으며,
아무도 호출하지 않은 함수는 존재하지 않는 것과 같습니다.

어느 한쪽만으로는 전체 그림이 되지 않습니다. `correlate_addr`가 있는 이유가 바로
그것입니다. 런타임 주소를 모듈과 RVA로 대응시키고, Ghidra나 IDA에서 찾아본 뒤,
양쪽을 함께 사용하십시오. Argus는 정적 분석 도구를 대체하기 위해서가 아니라
그 옆에서 함께 동작하도록 만들어졌습니다.

## 알아 둘 만한 두 가지 설계 결정

### 아키텍처 자동 라우팅

64비트 분석 도구를 32비트(WOW64) 대상에 어태치하는 것은 포인터 연산이 조용히
어긋나고 PE 파싱이 쓰레기 값을 내놓는 고전적인 원인입니다. Argus에는
`argus-router`라는 가벼운 프런트엔드가 있어, 대상 프로세스를 살펴 x86인지 x64인지
판별한 뒤 그에 맞는 `argus-rs` 빌드로 전달합니다. 설정하는 실행 파일은 하나뿐이며,
올바른 엔진이 대상마다 자동으로 선택됩니다.

### 증거 원장

에이전트는 그럴듯한 설명을 만들어내는 데는 능하지만, 그 설명에 근거가 없다는 사실을
알아차리는 데는 서툽니다. `record_hypothesis` / `verify_hypothesis` / `add_evidence`는
그 구분을 강제합니다. 주장은 먼저 가설로 기록되며, 증거가 첨부되고 검증을 통과한
뒤에야 확정된 사실이 됩니다. `query_hypotheses`를 사용하면 이후 세션이 모든 것을
다시 유도하지 않고 지난번에 멈춘 지점부터 이어갈 수 있습니다.

## 설치

### 사전 빌드된 바이너리

최신 릴리스를 내려받아 원하는 위치에 풀어 주십시오.

**[Releases](https://github.com/r0ptik/argus/releases)**

아카이브에는 `argus-router.exe`와 두 개의 엔진 빌드
(`argus-rs-x64.exe`, `argus-rs-x86.exe`)가 들어 있습니다. 같은 디렉터리에 두십시오.

### 소스에서 빌드

두 개의 Windows 타깃이 설치된 Rust 툴체인이 필요합니다.

```bash
rustup target add x86_64-pc-windows-msvc i686-pc-windows-msvc

git clone https://github.com/r0ptik/argus
cd argus
cargo build --release --target x86_64-pc-windows-msvc
cargo build --release --target i686-pc-windows-msvc
```

## 적용 범위와 사용에 관하여

Argus는 리버스 엔지니어링 및 프로그램 분석 도구입니다. 게임과 서버 보존,
네트워크 프로토콜 분석, 상호운용성을 위한 클린룸 재구현, 악성코드 분석,
크래시 및 메모리 손상 디버깅, 보안 연구와 같은 작업을 위해 만들어졌습니다.

운영 중인 서비스를 공격하기 위한 도구가 **아닙니다**. 치트 기능은 이 저장소에서
받지 않습니다 — [CONTRIBUTING.md](../../CONTRIBUTING.md)를 참조하십시오.

다른 프로세스를 열고 읽을 수 있는 권한이 필요하므로, 본인이 소유하고 있거나 분석
권한을 얻은 프로세스에만 사용하십시오. 분석 권한이 없는 소프트웨어에 어태치하는
것은 해당 소프트웨어의 약관이나 거주 지역의 법률을 위반할 수 있습니다. 그 책임은
도구가 아니라 사용자에게 있습니다.

## 지원 플랫폼

Windows 전용입니다. 메모리 접근 계층(`argus-winmem`)은 Win32 프로세스 및 메모리 API
위에 구축되어 있으며, 현재 Linux나 macOS 백엔드는 없습니다.

x86과 x64 대상을 모두 지원하며, WOW64에서 동작하는 32비트 프로세스도 포함합니다.

## 크레이트 구성

| 크레이트 | 역할 |
|---|---|
| `argus-router` | 프런트엔드 실행 파일; 아키텍처 판별과 전달 |
| `argus-rs` | MCP 서버; 도구 정의와 요청 처리 |
| `argus-engine` | 분석 엔진; 디스어셈블, 구조체 복원, 추적 |
| `argus-winmem` | Win32 프로세스 및 메모리 접근 |
| `argus-scan` | 패턴 및 값 스캔 프리미티브 |
| `evidence-core` | 주소, 모듈, RVA 및 증거 데이터 모델 |
