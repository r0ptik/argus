# Argus

[English](../../README.md) · [繁體中文](README.zh-TW.md) · [简体中文](README.zh-CN.md) · 日本語 · [한국어](README.ko.md)

**AI エージェントに**実行中**プロセスの証拠を渡す MCP サーバー。**

これまでのリバースエンジニアリング用 MCP サーバーは、いずれも*静的*解析ツール
— Ghidra、IDA、apktool — への橋渡しでした。ディスク上のファイルをエージェントに
渡すことはできますが、プログラムが今この瞬間に何をしているのかは教えてくれません。
あのバッファに何が復号されたのか、vtable のスロットが実行時にどのアドレスへ解決されたのか、
そのパケットを送出したのはどの呼び出し箇所なのか。

Argus はその「もう半分」です。実行中の Windows プロセスにアタッチし、実行時の証拠を返します。
実アドレス上の実バイト列、実際に実行されたコードの逆アセンブル、解決済みの IAT thunk、
生きたメモリから辿った呼び出しチェーン、そして「何が立証済みで何がまだ推測なのか」を
区別する仮説台帳です。

Argus はモデルの代わりに結論を出しません。アドレス、モジュール／RVA のコンテキスト、命令、
呼び出し元、呼び出し先、局所的な証拠を返し、あとは引き下がります。

## このプロジェクトが存在する理由

ゲームは死にます。運営がサーバーを閉じ、スタジオが畳まれ、ジャンルが移り変わる。
あとに残るのは、誰かのハードディスクの上でもうどこにも接続できなくなったクライアント
だけです。ソースもなく、プロトコルの資料もなく、話しかける相手のサーバーもない。
ある言語の話し方をまだ覚えているのに、もう誰も聞いていない実行ファイルだけが残ります。

Argus は、それを連れ戻すために作られました。

死んだゲームのサーバーを再構築するとは、そのプロトコルを復元することです。
パケットの構造、暗号化、オペコードのディスパッチ、通信の向こう側にある状態機械。
そして生き残っている唯一の仕様書は、クライアントのバイナリそのものです。
必要な資料は誰も書き残しておらず、知っていた人たちはとうに散り散りになっています。

静的解析はある程度までは連れて行ってくれます。しかし 20 年前のクライアントは
パックされ、文字列は暗号化され、ハンドラはプロセスが起動して初めて存在するテーブルを
経由してディスパッチされます。だから実際に動かし、その様子を観察する —— 次の節は
その話です。

このツールの目的はそこにあります。生きているものに押し入るためではなく、
死んでしまったものにもう一度口を開かせるためのものです。

## なぜ実行中のプロセスまで見に行くのか

**CPU は暗号文を実行できません。**

プログラムがディスク上でどれだけ自分を守っていても — パッキング、文字列の暗号化、
命令の仮想化、ロード時に解決される import — プロセッサがそのコードを走らせる前に、
そのすべてを元に戻さなければなりません。実行されるその瞬間、本物の命令と本物のデータは
平文のままメモリ上に置かれています。**そうならざるを得ないのです。**
これは特定のプロテクタの出来が悪いという話ではなく、プロセッサの動作原理から来る
必然であり、どれほど難読化を重ねても回避できません。

つまり、この 2 つのアプローチはそもそも別のものを読んでいます。

- **静的解析が読むのはファイル。** 作者が出荷したもの。
- **実行時解析が読むのはファイルが変化した結果。** マシンが実際に走らせているもの。

両者が食い違ったとき、真実は後者の側にあります。

| 状況 | 静的解析ツール | Argus |
|---|---|---|
| パック／自己復号コード | パッカーが見える | メモリ上で展開済みのバイト列を逆アセンブル |
| vtable 経由の間接呼び出し | `call [rax+0x18]` が見える | スロットを具体的な呼び出し先に解決 |
| 実行時に解決される import | thunk スタブが見える | thunk を実際の API に解決 |
| 復号後のバッファ内容 | 何も分からない | 平文を読み出す |
| 40 箇所の呼び出し元のうち実際に発火したのはどれか | 推測 | 実行されたものを記録 |

### 静的解析が勝る点

逆方向のトレードオフもはっきり書いておきます。静的解析ツールは、一度も実行されない
ものを含めて**すべての**パスを見ることができます。Argus が見えるのは実際に走った
ぶんだけです。通らなかった分岐は実行時の証拠を一切残しませんし、誰からも呼ばれない
関数は存在しないのと同じです。

どちらか一方だけでは全体像になりません。`correlate_addr` があるのはそのためです。
実行時アドレスをモジュールと RVA に対応付け、Ghidra や IDA で引き、両方を突き合わせて
使ってください。Argus は静的解析ツールを置き換えるためではなく、その隣で動くために
作られています。

## 知っておく価値のある 2 つの設計判断

### アーキテクチャの自動ルーティング

64 ビットの解析ツールを 32 ビット（WOW64）ターゲットにアタッチすることは、
ポインタ演算が静かに壊れ、PE 解析がゴミを返す古典的な原因です。
Argus には `argus-router` という軽量なフロントエンドがあり、対象プロセスを調べて
x86 か x64 かを判定し、対応する `argus-rs` のビルドへ振り分けます。
設定する実行ファイルは 1 つだけで、正しいエンジンがターゲットごとに選ばれます。

### 証拠台帳

エージェントはもっともらしい説明を作るのが得意で、その説明に裏付けがないことに
気づくのが苦手です。`record_hypothesis` / `verify_hypothesis` / `add_evidence` は
その区別を強制します。主張はまず仮説として記録され、証拠が添付され検証を通過して
初めて確定した事実になります。`query_hypotheses` を使えば、後のセッションが
すべてを導出し直すことなく前回の続きから再開できます。

## インストール

### ビルド済みバイナリ

最新のリリースをダウンロードし、任意の場所に展開してください。

**[Releases](https://github.com/r0ptik/argus/releases)**

アーカイブには `argus-router.exe` と 2 つのエンジンビルド
（`argus-rs-x64.exe`、`argus-rs-x86.exe`）が含まれます。同じディレクトリに置いてください。

### ソースからビルド

Windows 向けの 2 つのターゲットを導入した Rust ツールチェインが必要です。

```bash
rustup target add x86_64-pc-windows-msvc i686-pc-windows-msvc

git clone https://github.com/r0ptik/argus
cd argus
cargo build --release --target x86_64-pc-windows-msvc
cargo build --release --target i686-pc-windows-msvc
```

## 対象範囲と利用について

Argus はリバースエンジニアリングおよびプログラム解析のためのツールです。
ゲームとサーバーの保存、ネットワークプロトコル解析、相互運用性のためのクリーンルーム
再実装、マルウェア解析、クラッシュやメモリ破壊のデバッグ、セキュリティ研究といった
用途を想定しています。

稼働中のサービスを攻撃するためのものでは**ありません**。チート機能はこのリポジトリでは
受け付けません — [CONTRIBUTING.md](../../CONTRIBUTING.md) を参照してください。

他プロセスを開いて読み取る権限を必要とするため、自分が所有しているか、
解析の許可を得ているプロセスにのみ使用してください。解析の権限がない
ソフトウェアにアタッチすることは、そのソフトウェアの規約や、お住まいの地域の
法令に違反する可能性があります。その責任はツールではなく利用者にあります。

---

## 対応プラットフォーム

Windows のみです。メモリアクセス層（`argus-winmem`）は Win32 のプロセス／メモリ API の
上に構築されており、現時点で Linux および macOS のバックエンドはありません。

x86 と x64 の両方のターゲットに対応しており、WOW64 上で動作する 32 ビットプロセスも含みます。
